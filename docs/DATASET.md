**项目名称**：基于检索增强的 PDF 知识库问答系统
**课程**：机器学习综合实践
**日期**：2026-10-02

---

## 一、数据集来源

本项目使用 **CMRC2018**（Chinese Machine Reading Comprehension 2018），由**哈工大讯飞联合实验室（HFL）**发布，是中文机器阅读理解领域的公开基准数据集。

原始数据通过 HuggingFace 镜像（hf-mirror.com）下载。本项目用到三个仓库：

| 序号 | 仓库 | 用途 | 链接 |
|---|---|---|---|
| 1 | `hfl/cmrc2018` | 微调训练集、端到端问答评测集 | https://huggingface.co/datasets/hfl/cmrc2018 |
| 2 | `jinaai/longcontext-cmrc2018-zh` | 检索评测的语料库与查询 | https://huggingface.co/datasets/jinaai/longcontext-cmrc2018-zh |
| 3 | `jinaai/longcontext-cmrc2018-zh-qrels` | 检索评测的标准答案（相关文档标注） | https://huggingface.co/datasets/jinaai/longcontext-cmrc2018-zh-qrels |

第 2、3 项是把 CMRC2018 转换成 **BEIR 检索格式**后的版本，含语料库（corpus）、查询（queries）和相关性标注（qrels）。使用 BEIR 格式的原因：CMRC2018 原始格式是"一篇文章 + 若干问题 + 答案片段"，而检索评测需要的是"从一大批文档里找出和查询相关的那篇"，两者任务定义不同。BEIR 格式把每篇文章独立成一条语料，并标注每条查询对应哪篇文档相关，正好可以直接算检索指标。

下载脚本：`eval/download_data.py`（用 `curl` 走镜像，国内可直连）。

### 2.2 清洗与去重后的实际使用规模

| 用途 | 规模 | 来源 |
|---|---|---|
| **检索评测集** | **934 篇语料 / 1149 条查询** | `lc_corpus` 去重后 + `lc_queries` |
| **微调训练集** | **8031 句对** | 官方训练集清洗后划分 |
| **微调验证集** | **437 句对**（109 篇文档） | 同上 |
| **端到端问答评测集** | **200 条** | 官方验证集随机抽样 |

语料文本长度（按 `bge-small-zh-v1.5` 分词器统计）：

| 指标 | 数值 |
|---|---|
| 平均长度 | 582.1 token |
| 中位数 | 586 token |
| 90 分位 | 840 token |
| 最大值 | 975 token |
| **超过模型上限 512 token 的比例** | **63.5%** |

最后一行是本研究的关键发现之一：**超过六成的文档长度超出向量模型的处理上限**，超出的部分会被静默丢弃。详见项目 README 与论文第四章、第五章。

## 三、数据清洗过程

### 3.1 语料去重（1149 → 934）

检索语料中存在完全重复的文本，去重后从 **1149 篇减少到 934 篇**，共移除 215 篇。

去重是必要的：若同一篇文章在语料库中出现两次，检索命中任意一篇都会被判为正确，指标会虚高。

### 3.2 查询筛选

去重后重新建立查询与语料库的对应关系（`build_retrieval_benchmark`），只保留**标准答案文档确实存在于语料库中**的查询，避免出现无法判定的查询。

### 3.3 训练集清洗

官方训练集（10142 条）经过以下处理：

| 步骤 | 说明 | 剩余 |
|---|---|---|
| 原始 | CMRC2018 官方训练集 | 10142 条 |
| 脏样本过滤 | 丢弃答案为空、答案位置越界、问题或文章过短的样本 | — |
| 句对去重 | 同一（问题，文章）组合只保留一条 | 9236 句对 |
| **剔除数据泄漏** | 见 3.4 | **8468 句对** |

### 3.4 数据泄漏剔除（重要）

检查发现：**CMRC2018 官方训练集与本项目的检索评测语料存在文本重叠**——评测语料 934 篇中，有 **204 篇（21.8%）** 能在训练集中找到完全相同的原文。

若不处理，微调时模型已经"见过"这些文档，评测分数会虚高，**微调前后的对比也就不成立**。

处理方式：以评测语料中的 934 篇文本为排除集，把训练集中文章内容与之完全相同的样本全部剔除，共**丢弃 768 条句对**。

这一步有独立复算验证：

```
评测语料（去重后）: 934 篇
训练集句对: 9236 → 剔除后 8468，丢弃 768 对
训练集与评测语料完全相同的文档: 204 篇 (21.8%)
```

### 3.5 数据集划分

训练集与验证集**按"文章"为单位划分**，而不是按"句对"随机划分，划分比例 95 : 5。

理由：同一篇文章可能对应多个问题。若按句对随机划分，同一篇文章会同时出现在训练集和验证集里，验证损失就失去意义了。

划分结果：**8031 句对训练 / 437 句对验证**（验证集含 109 篇文档）。随机种子固定为 42，划分可复现。

## 四、数据使用方式

本项目对同一份数据的**三种用法**，各自独立：

### 用法一：微调向量检索模型

- **数据**：8031 个（问题，正例文章）句对
- **方式**：对比学习，`MultipleNegativesRankingLoss`
- **负样本**：不使用额外负样本，**批内其他问题的正例文章即为负样本**（批大小 16，则每个问题有 15 个负样本）
- **目的**：让通用向量模型学会本领域的"问题 → 段落"对应关系
- **脚本**：`eval/finetune_embedding.py`

### 用法二：检索方案对比评测

- **数据**：934 篇语料 + 1149 条查询 + qrels
- **方式**：对 6 种检索方案计算 P@1 / Recall@k / MRR@10 / nDCG@10（BEIR 口径）
- **目的**：把检索方案的选择从"凭感觉"变成"看数据"
- **脚本**：`eval/run_retrieval_eval.py`

### 用法三：端到端问答评测

- **数据**：官方验证集**随机抽样 200 条**（随机种子 42，非取前 200 条）
- **方式**：完整走一遍"检索 → 拼 Prompt → 调用大模型生成"，再与标准答案比对
- **指标**：EM、F1、包含率，并按"检索是否命中"做失败归因
- **脚本**：`eval/run_e2e_eval.py`

## 五、已知问题与局限

这部分如实列出，避免使用者误判数据适用范围。

### 5.1 语料与训练集的重叠已处理，但不保证完全干净

本次只剔除了**文章内容完全相同**的样本（204 篇 / 768 对句对）。若训练集中存在**高度相似但不完全相同**的文章，本方法检测不到，仍可能造成轻微泄漏。影响程度未做定量评估。

### 5.2 每条查询只有 1 篇相关文档

CMRC2018 的单跳性质决定了 qrels 中每条查询恰好对应 1 篇相关文档。因此：

- **Recall@k 的含义被简化**了——不存在"召回多篇相关文档中的一部分"这种情况；
- 也无法评测"多跳检索"或"多文档聚合"能力。

这是数据集本身的限制，不是处理方法导致的。

### 5.3 检索评测语料与线上知识库不是同一份数据

| | 检索评测 | 线上系统 |
|---|---|---|
| 数据 | CMRC2018 语料（934 篇，维基百科风格） | 用户上传的 PDF（如员工手册） |
| 特点 | 段落长短不一，无章节结构 | 有"第X章""第X条"等结构标记 |

**这一点很重要**：评测集上没有章节结构，所以 `smart_chunk` 那套"按第X章切分"的逻辑在评测中**完全不起作用**（实测一篇都没切开）。线上 PDF 有结构标记，分块效果会不同。

因此**评测结论不能直接外推到线上场景**。论文中涉及分块的结论，都注明是在 CMRC2018 语料上得到的。

### 5.4 端到端评测的 200 条样本量偏小

200 条足以看出"检索是否命中"这个二分结论（197 命中 / 3 未命中），但**不足以支撑精细的指标比较**——例如 EM 从 0.045 到 0.765 这种巨大差异是可信的，而包含率 0.870 与 0.855 之间 1.5 个百分点的差距（约 3 条题的差别），在 200 条样本上**不具备统计显著性**。
